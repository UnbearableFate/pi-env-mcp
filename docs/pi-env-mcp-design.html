设计说明 · pi-env-mcp

每台主机 1 条 SSH 连接，承载全部工具调用

agent 通过 MCP 调用本机的 pi-env-mcp。它对每台主机只开一条 ssh，远端的 pi-env daemon 执行命令、终端、文件操作和远端 MCP 服务。

连接

建连付一次 2.4 秒，之后每条命令约 6 毫秒

建连的三次 ssh 来自上游 pi-env 的 connectSsh，pi-env-mcp 不改它。login shell 只在启动 daemon 时读一次 profile；此后命令继承 daemon 的环境。daemon 30 秒收不到数据就退出，并杀掉它启动的进程组。

状态

后台作业不怕断线；其余状态随连接或 serve 消失

远端 MCP

远端 MCP 服务跑在同一条连接里，工具和 bash 并列

非字母数字下划线的字符变成 _；过长或冲突的名字加哈希后缀。描述、输入输出 schema 和 annotations 都保持服务原样。

serve 启动时最多等 8 秒（--mcp-wait），让远端工具出现在第一次列表里；更慢的服务之后通过 tools/list_changed 出现。服务退出时，daemon 杀掉它的整个进程组；要留下的子进程必须自己 setsid。

会话

每个 agent 只占 1 个会话；Miyabi 一条 master 最多 10 个

一个 serve 在一台主机上只占 1 个会话，不管它跑多少命令、终端和 MCP 服务。会话上限来自 sshd 的 MaxSessions，按每条 master 连接计。

信任

三道检查：主机密钥、免交互登录、daemon 哈希

  • trust 扫描主机出示的密钥，与你的 ~/.ssh/known_hosts 比对：一致就接受，没有记录就要你确认指纹，不一致就拒绝，除非加 --yes。
  • ssh 用 BatchMode，不弹密码提示；关闭 agent、X11 和端口转发。需要一次性密码的主机用 shareConnection，借你自己开的 master。
  • daemon 每次启动前都校验 sha256；远端不需要 root，不开端口，不常驻服务。

代码

server 管工具，session 管连接，mcp 管远端服务

原则：完全复用 pi 系列的最新做法，不保留兜底；子命令和退出码与上游一致，只为 Claude Code 和 Codex 做适配。pi 发布这些功能后，依赖回到 npm，vendor/ 删除。

边界

notifyd 和账本导出这一版仍走 ssh

  • 远端 MCP 服务的 resources、prompts，以及服务端发给客户端的请求（sampling、elicitation），都不转发。
  • 只支持 stdio 服务；HTTP 服务不需要远端主机，直接注册给 agent。
  • 现在的 vendor 构建只带 Linux daemon；macOS、Windows、Android 主机要另外构建。
